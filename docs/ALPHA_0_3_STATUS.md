# Alpha 0.3 implementation status

> Historical document-driven-runtime snapshot. It is superseded by
> `docs/checkpoints/CP-AEYLA-0.3.2.md`; retained to preserve milestone history.

## Implemented in source

### Shared product runtime

- Shared product application model for standalone and VST3.
- 14 logical fixtures with authored Rig 10 and temporary Rig 14 activation.
- Deterministic Solid, Gradient, Wave, Noise and Chase sampling.
- Semantic RGBWALUV transformation.
- One 512-byte DMX universe generated by the shared compiler.
- MIDI notes 36–43 through bounded host ingress.
- Manual executor pads and host MIDI use the same runtime command path.
- Non-realtime event consumption from APP/VST3 idle path.
- Startup disarmed and null-backend arm rejection.
- End-to-end blackout, backend-loss and reload safety.

### Versioned project document

- Schema major/minor versioning.
- Stable project UUID and logical fixture/profile/look identifiers.
- Embedded fixture profiles with reorderable semantic channel slots.
- Fourteen fixture positions with patch, enable state and normalized layout coordinates.
- Authored looks, visual parameters, MIDI mappings, output settings and UI state.
- Asset/checksum records with normalized package-relative path validation.
- Deterministic UTF-8 JSON serialization and strict bounded parsing.
- Duplicate-key, malformed, truncated, deeply nested and oversized input rejection.
- Duplicate fixtures/profiles/mappings, missing profiles, patch overlap and universe-boundary validation.
- Persisted Output Arm is ignored and cleared during deserialization.
- Same-major future-minor documents remain readable; unsupported schema majors are rejected.
- ApplicationModel consumes the loaded document for profile channel order, physical address, visual source and runtime metadata.
- Project reload always ends disarmed and in blackout; invalid reload produces a zero DMX frame.
